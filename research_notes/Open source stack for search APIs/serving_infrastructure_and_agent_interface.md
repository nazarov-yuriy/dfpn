## KQ1. What languages and runtimes do the providers disclose for serving, and what do their latency claims actually rest on?

### Takeaway
Only Exa discloses a serving language (C++ inner loop, Rust elsewhere, TypeScript/Playwright for crawling, PyTorch for models), confirmed by both engineering posts and job ads; Perplexity discloses its inference runtime (Triton + TensorRT-LLM + proprietary CUDA runtimes) but not its search-serving language; Keenable's only public code is a Rust CLI. Every sub-500 ms latency headline is vendor-measured and in at least two cases (Exa Instant, Keenable realtime) is contradicted or qualified by other measurements.

### Cited Findings
- Exa's vector-DB hot path is C++ ("hot path in C++ rather than Rust"), with clustering, lexical compression and "assembly optimizations in Rust" in Exa 2.0 (2025-10-10) — [Exa 2.0](https://exa.ai/blog/exa-api-2-0); earlier vector-DB post requirements "<100ms, >500 QPS" over "billions of 4096-float vectors" — [exa.md summary of Exa vector-DB post, Dec 2024](https://exa.ai/blog/exa-api-2-0).

### Inferences
- [inferred] Cost scales with stored items, not queries, for all small engines (Mwmbl's explicit design goal, Marginalia's disk-bound budget, ChatNoir's 115 TB); the open engines therefore cap at 10^8–10^9 pages, two orders of magnitude below the 10^10–10^11 claimed by Exa, Perplexity, Keenable, Ceramic.
- [inferred] Stract's archiving after NGI0 funding ended and OWI's unlaunched API after €8.5M suggest sustained operation, not initial build, is the binding constraint for open engines; Marginalia's model (grants + API licences, one server) is the one that has persisted.

## KQ8. Learning path for the serving, data, inference and agent-interface layer

### Takeaway
Learn the layer in the order the evidence shows the vendors built it: a Rust/C++ serving core with explicit percentile targets, a lakehouse (object store + Parquet/Lance + Ray or Spark) feeding it, an inference tier (TEI/Triton for small models, vLLM/SGLang/TensorRT-LLM for LLMs) with cost-per-million-queries tracking, and an agent surface that is Streamable-HTTP MCP + OAuth + keyless tier + SKILL.md/CLI.

### Cited Findings (ordered path, each item points at the evidence that motivates it)
1. **Read two complete engines end to end**: Marginalia (single NUMA server, AGPL, ~$200/month, 5-day crawl) and Stract (Rust, own crawler, archived) — [Marginalia README](https://github.com/MarginaliaSearch/MarginaliaSearch); [marginalia.nu 2026-07-22](https://www.marginalia.nu/log/a_138_systemdocker/); [Stract README](https://github.com/StractOrg/stract).
2. **Serving core in Rust with a C++/SIMD inner loop**, targeting "<100ms, >500 QPS" over binary-quantised vectors and clustered search — [Exa vector DB and Exa 2.0](https://exa.ai/blog/exa-api-2-0); job ads require "high performance language (C++, Rust, etc.)" — [Exa Ashby board](https://api.ashbyhq.com/posting-api/job-board/exa).
3. **Percentile discipline and honest measurement**: compare p50/p95 from a stated region and defeat caches with randomised queries — [Perplexity 2025-09-25](https://www.perplexity.ai/hub/blog/architecting-and-evaluating-an-ai-first-search-api); [Exa Instant method](https://exa.ai/blog/exa-instant); [Keenable live board](https://keenableai.github.io/needle/).
4. **Lakehouse data layer**: object storage + Lance/Parquet + Ray Data for GPU batch embedding (Exa) or Spark over Delta/Iceberg/Hudi (Exa 2026 job ad; OWI daily Spark jobs on HPC via Magpie, Parquet + CIFF outputs) — [exa-d](https://exa.ai/blog/exa-d); [Exa job board](https://api.ashbyhq.com/posting-api/job-board/exa); [Hendriksen et al. 2024](https://elib.dlr.de/210780/1/hendriksen_2024.pdf); Common Crawl's Parquet URL Index as a free practice dataset — [Common Crawl](https://commoncrawl.org/blog/the-columnar-index-is-now-the-url-index).
5. **Inference tier**: reproduce Perplexity's pattern — small routers, pooled sub-1B embedding/reranker models on one GPU, TP-sharded LLMs behind Triton/TensorRT-LLM in Kubernetes; track TTFT, tokens/s/user, cost per million queries; test load-balancing policies at the worst percentile — [NVIDIA case study 2024-12-05](https://developer.nvidia.com/blog/spotlight-perplexity-ai-serves-400-million-search-queries-a-month-using-nvidia-inference-stack/). Open tools to practise with: vLLM, SGLang, text-embeddings-inference, Triton, ONNX Runtime [training knowledge, unverified].
6. **Token-efficiency models at query time**: Keenable's query-conditioned token classifier halves payload with no latency — [Dynamic Snippets 2026-10-15](https://keenable.ai/blog/keenable-snippets-full-page-cost-reduction); Brave's token-budgeted LLM Context endpoint — [Brave API](https://brave.com/search/api/).
7. **Cost sizing**: ChatNoir's 124 nodes/115 TB for 1.6B pages, tantivy's ~13 TB BM25 index and $400/month S3, Exa's ~$5M H200 cluster, FineWeb's 6,000 H100-hours per classifier pass — [Bevendorff 2018](https://downloads.webis.de/publications/papers/bevendorff_2018.pdf); [tantivy post](https://fulmicoton.com/posts/commoncrawl/); [Exa 2.0](https://exa.ai/blog/exa-api-2-0); [FineWeb](https://arxiv.org/html/2406.17557v2).
8. **Agent surface**: build an MCP server with an official SDK over Streamable HTTP, implement OAuth resource-server metadata and RFC 8707, structured tool output, `search` + `fetch` tools with age/freshness parameters, a keyless IP-limited tier and optionally x402 — [MCP changelog 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/changelog); [MCP SDKs](https://modelcontextprotocol.io/docs/sdk); [Keenable pricing/x402](https://keenable.ai/pricing); [x402.org](https://www.x402.org/).
9. **Skills and CLIs**: ship a SKILL.md plus a CLI with YAML/JSON output as Keenable, Firecrawl and Brave do — [Keenable SKILL.md](https://app.keenable.ai/SKILL.md); [firecrawl/cli](https://github.com/firecrawl/cli); [brave-search-cli](https://github.com/brave/brave-search-cli).
10. **Wire it into an open front-end**: Morphic or Perplexica/Vane with SearXNG, then your own engine as a provider; self-host Firecrawl (Postgres + Redis + Playwright) for fetch — [Morphic README](https://github.com/miurla/morphic); [Firecrawl self-host](https://docs.firecrawl.dev/contributing/self-host).

### Inferences
- [inferred] A practitioner can reproduce every layer except two with open tools: the web-scale fresh index (10^10+ pages, continuous recrawl) and the anti-bot rendering capacity (Firecrawl's fire-engine, Brave/Perplexity's crawl fleets); those are where the vendors' capital goes and where open engines stop at 10^8–10^9 pages.
- [inferred] The skill set the vendors hire for, per Exa's ads, is Rust/C++ systems + Python/PyTorch + Spark/lakehouse + TypeScript/Playwright; no ad mentions Kubernetes, Kafka or an observability vendor, so those are table stakes rather than differentiators.

### Gaps
- No vendor job ad or post fetched names Kubernetes except Perplexity (via NVIDIA), Kafka, Beam, Flink, Nomad, Prometheus/Grafana/Datadog, or a CDN; their use is assumed, not evidenced.
- Exa's "Knowledge Engine – Query Engine" and "Research Engineer, Index Intelligence/Content Understanding" postings were not reached within the Ashby JSON window read (first 100k of 732k characters via WebFetch; the Bash parse was truncated at 150 lines), so any serving-side technologies they name are missing.
- All GitHub star/activity/licence verification for the open-source equivalents is outstanding (GitHub blocked for this session); the report writer should treat language/licence statements marked [training knowledge] as unverified.
